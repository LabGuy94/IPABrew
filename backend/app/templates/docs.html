IPABrew Documentation

Local reconstruction, IPA utilities, tree workflows, and API reference

Overview

IPABrew reconstructs proto-language forms from related IPA cognates. The web UI is best for interactive tree editing and visualization. The CLI and API expose the same local domain logic for repeatable dataset sampling, reconstruction, alignment, feature inspection, and dating workflows.

The project is a local research/demo app for experimenting with cognate sets, family-tree shapes, reconstruction methods, and supporting phonological analysis tools.

Quick start

git clone https://github.com/LabGuy94/IPABrew.git
cd IPABrew
pip install -e .
ipabrew web

Open the app for the tree editor or keep using this page at /docs as an in-app reference. The development server runs on port 8080 by default. Run pip install -e . from inside the cloned IPABrew repository folder; after installation, ipabrew can be run from any folder as long as the same Python environment is active. For tests, install pip install -e .[test]. IPABrew requires Python 3.10+ and targets macOS, Linux, and Windows through Python/Flask, though dependency installation can vary by platform, especially for ML packages such as PyTorch.

Web UI usage

  1. Name the root language. The root is always reconstructed.
  2. Add intermediate branches and descendant languages.
  3. Enter IPA forms for all descendants. Empty intermediate IPA fields are reconstructed bottom-up.
  4. Use comma-separated IPA values to reconstruct multiple word sets from the same tree shape.
  5. Select Machine Learning (DPD) or Algorithmic reconstruction in the results panel.

CLI usage

The ipabrew CLI runs the web app and local domain functions directly. Web-launch commands can open a browser automatically, while analysis commands print JSON to stdout. Validation/runtime failures print to stderr and return non-zero exit codes. 

ipabrew
ipabrew help
ipabrew help COMMAND

Dataset and reconstruction commands

Inputs, validation rules, and reconstruction envelopes.

CommandPurposeKey options/inputs
ipabrew sample Read a slice of bundled Romance dataset rows. --count, --offset
ipabrew search QUERY Search dataset IPA values for a substring. QUERY, --limit
ipabrew reconstruct --index N Reconstruct from one dataset row by index. --index
ipabrew reconstruct --words ... Reconstruct from explicit cognates (minimum two words). --words, optional --languages (same length as words)
ipabrew reconstruct-tree Reconstruct an entire tree JSON bottom-up. --tree-json inline JSON or file path, --method ml|algorithm
ipabrew align WORD ... Compute a multiple alignment for IPA words. At least two words

IPA, dating, and model commands

Analysis outputs, estimation inputs, and model availability.

CommandPurposeKey options/inputs
ipabrew distance WORD1 WORD2 Return IPA feature edit distance, normalized distance, and divergence estimate. WORD1, WORD2
ipabrew features WORD Return articulatory feature vectors per IPA segment. WORD
ipabrew date --ned N Map normalized edit distance to a divergence estimate. --ned
ipabrew date --cognate-pct C Estimate divergence years via retention-rate formula. --cognate-pct, optional --retention-rate
ipabrew model-status Report whether DPD model is currently loaded/available. Optional --load to initialize before checking

If your shell says ipabrew is not found, run pip install -e . again from the cloned repository root.

JSON tree input example

reconstruct-tree accepts either an inline JSON object or a path to a JSON file. Leaves must provide IPA input. Branches may provide IPA input or leave it empty for reconstruction. 

{
  "label": "Proto-Test",
  "children": [
    {
      "label": "Western",
      "children": [
        {"label": "French", "ipa": "pɛːr"},
        {"label": "Spanish", "ipa": "padre"}
      ]
    },
    {
      "label": "Eastern",
      "children": [
        {"label": "Italian", "ipa": "padre"},
        {"label": "Romanian", "ipa": "patre"}
      ]
    }
  ]
}

Reconstruction methods and fallback behavior

ML (DPD neural model)

Fallback signal and method traceability.

The ML path uses the bundled DPD bidirectional Transformer when checkpoint and model data are present and loaded. This is the same model family described by Lu, Xie & Mortensen (ACL 2024). The selected checkpoint is model/checkpoints/epoch34.ckpt, with configuration in model/checkpoints/model_config.yaml. The checkpoint was trained on combined SIGTYP 2022 and WikiHan data aggregated under model/data/combined/. In tree reconstruction responses, the output includes method_used so callers can confirm whether reconstruction actually ran with ML or algorithmic fallback.

Algorithmic (LingPy)

Baseline path and explicit method selection.

The algorithmic path uses LingPy multiple-sequence alignment and majority voting over alignment columns. It is always available and is used explicitly when --method algorithm is chosen or automatically when ML is unavailable.

Data/source notes and limitations

Dataset sample and search commands use the bundled Meloni Romance IPA table. Divergence dating is an estimate derived from Swadesh-style retention and normalized edit distance mappings; treat results as a comparative guide rather than an absolute historical date. IPA segmentation and distance depend on panphon coverage for the supplied symbols.

Glottochronology and divergence dating

Swadesh retention formula

t = ln(c) / (2 * ln(r)) * 1000

Where c is cognate retention proportion and r is retention rate (default 0.86).

NED rangeEstimated ageCategory
0.0-0.10-500Dialects
0.1-0.3500-1,500Romance languages
0.3-0.51,500-3,000Germanic family
0.5-0.73,000-5,000IE subfamilies
0.7-1.05,000-10,000Deep/uncertain

Calibration data is available through /api/date/calibration for known language-family splits, including Romance, Proto-Germanic, Balto-Slavic, and Proto-Indo-European reference points.

Frontend notes

  • Single-page vanilla JavaScript app (no frontend build step).
  • D3-based tree visualization for reconstructed outputs.
  • IPA keyboard support for phonetic input.
  • Tree editor supports comma-separated batch reconstruction.
  • Built-in demo families include Romance, Sinitic, Burmish, Karen, Aztecan, and Purus.
  • Export controls live in the frontend JavaScript alongside tree rendering and API calls.

Development notes

  • Install CLI into your active Python environment with pip install -e ..
  • Install test dependencies with pip install -e .[test].
  • Use ipabrew web for app launch or ipabrew docs to open docs directly.
  • Use ipabrew help and ipabrew help COMMAND for CLI reference.
  • Run tests with pytest backend/tests.
  • The DPD model loads when the Flask app starts; first startup can take a few seconds when model assets are present.
  • To add demo language families, update backend/app/static/js/app.js.
  • cd backend && python run.py also starts the Flask debug server on port 8080 for development.
  • Model checkpoint and training details are documented in model/README.md.
